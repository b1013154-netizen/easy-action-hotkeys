# 技術選定と構成

## 確定要件

- レポジトリ名 `easy-action-hotkeys`。ツール専用のフォルダに格納する。
- WindowsとMacに対応する。
- 画像指定とボタン認識を両方用意する。
- 実際の操作の記録と、手動の動作登録を両方用意する。
- 操作セットは100件まで。
- 特定のアプリだけに限定しない。ブラウザの主な想定はGoogle Chrome。
- 履歴削除は期間を選び、保存パスワードなどは項目を指定する。

## Python + PySide6 を採用する理由

Windows専用の暫定案はC#とWPFだったが、ユーザー回答によりMacも対象となった。PythonとQtを用いて共通GUIを作り、入力操作・画面認識・OS別のアクセシビリティを分離する構成を採用した。

| 技術 | 採用する用途 |
| --- | --- |
| PySide6 / Qt | 日本語GUI、画面選択、画像範囲指定、画面キャプチャ、メインスレッドへの通知 |
| pynput | グローバルキー監視、記録、マウス・キーの送信 |
| OpenCV / Pillow | 画像照合、PNG保存、画像と画面座標の対応 |
| pywinauto / UI Automation | Windowsのボタン認識 |
| PyObjC / ApplicationServices | MacのAccessibilityによるボタン認識 |
| PyInstaller | Pythonのインストール不要な配布物の生成 |

QtのスクリーンキャプチャはGUIスレッドで実行し、操作の再生は別スレッドで行う。Windows UIAはCOMオブジェクトを共有スレッドから直接使わず、専用スレッドに集約する。画像の物理ピクセル位置から画面の論理座標へ変換し、負の座標を持つモニターも扱う。

## ファイル構成

- `main.py`：Windows DPIの初期化と起動。
- `easy_action/model.py`：100件制限、キー重複・値検証、JSON保存とバックアップ。
- `easy_action/ui.py`：初心者向け登録画面、対象選択、手順編集、記録案内。
- `easy_action/input.py`：キー監視とマウス・キー操作の記録。
- `easy_action/runner.py`：逐次再生、待機、停止、キーの解放。
- `easy_action/accessibility.py`：OS別の対象認識とチェック状態の読み取り。
- `easy_action/desktop.py`：画面キャプチャ、画像照合、スクリーンショット保存。
- `tests/`：データ・認識・GUI・再生の検証。
- `verification/`：画面レンダリングとWindows専用の実動作テスト。
- `.github/workflows/`：WindowsとMacの検証・ビルド。

## 初版の境界

ボタンを認識できないアプリには画像指定を使う。UI情報が同じ候補や、同じ画像が複数ある場合は停止する。ブラウザ拡張を必須にはせず、DOMセレクターの編集も利用者に求めない。

Chromeの履歴削除は、期間と項目の案内を見ながら画面操作を登録する方式。F7でチェック状態を読み取り、再生時に指定の状態へ合わせる。保存パスワードは別の操作としてGoogleパスワードマネージャー画面で対象を指定する。期間選択をブラウザの内部APIで強制する機能、Googleアカウント全体の活動履歴の削除は実装しない。

キーはOS・他アプリへも届くため、競合しない組み合わせを選ぶ。自動起動、システムトレイ常駐、複雑な条件分岐、OCR、任意のシェルコマンドの実行は初版の対象外。

Macの実機検証・配布署名は別のMac環境が必要。両OSでの同等の動作を検証済みとは扱わない。
