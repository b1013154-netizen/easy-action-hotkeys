# 検証結果

検証日：2026年10月8日（日本時間）。ローカル環境はWindows 11 x64、Python 3.12.14、PySide6 6.11.2。

## 自動テスト

`python -m unittest discover -s tests -v`：**17件成功**。

- 操作セット100件の上限と、正規化した呼び出しキーの重複。
- 停止・記録用キー、異常値、未解放キーの拒否。
- 保存・読み込み、直前のバックアップ、無効な保存で元データを壊さないこと。
- 画像の照合、モニターの原点と倍率の変換、画像が複数あるときの停止、未検出・壊れた画像。
- 複数画面の画像保存。
- 対象ボタンのOS・アプリ・種類・識別子による照合。
- 日本語と改行を含む登録の保存、全動作の入力画面生成。
- 再生の順序、停止時のキー解放。
- チェック状態を既に指定状態の場合に反転しないこと。
- キー長押しによる重複起動の防止と、記録終了時の修飾キー解放。

これらのテストはダミーの入力バックエンドを使い、通常のアプリを操作しない。

## Windowsでの実動作確認

`verification/windows_smoke.py`：**成功**。

別プロセスの専用テスト画面を作り、対象を検証してから、その画面だけを操作した。

- 位置クリックで入力欄へフォーカスを移す。
- 「日本語 test」を入力する。
- UI Automationからボタンを認識し、1回クリックする。
- チェックをオンにする動作を2回実行し、オンのままになること。
- Qtで画面を取得しPNGを保存する。
- Ctrl+Alt+F10のグローバルキー検知が1回通知されること。
- 実キー入力を記録し、F8で記録を終了すること。

通常の制限環境ではデスクトップのマウス座標を取得できなかったため、テスト画面だけを操作する確認は通常のWindowsデスクトップにアクセスできる実行環境で行った。UIAのCOMオブジェクトは専用スレッドに集約し、異なるスレッドから直接使わないように修正した。

日本語のメイン画面と文字入力画面をレンダリングし、表示を目視確認した。

## Windows配布用EXE

PyInstallerでWindows x64の実行ファイルを生成し、`--diagnose` による配布物の起動確認が**成功**した。13種類の動作画面、Qt、OpenCV 5.0.0、UI Automationのライブラリ読み込みを確認し、終了コード0で終了した。

ビルド環境のPATHにあるPopplerのICU DLLが混入すると、QtCoreが要求するWindowsのICU APIと合わず起動できないことを確認した。配布準備で混入したICU DLLを取り除き、Windows標準のICUを使うよう修正した。この処理は `prepare_release.py` に含め、Windowsのビルドスクリプトから実行する。

## 未検証・制約

- Macの実機での入力、Accessibility、画面収録権限、.appの配布・署名。
- Chromeでの実際の履歴・Cookie・パスワードなどの削除。利用者データの削除テストは行っていない。
- すべてのアプリ、ブラウザ、画面言語・テーマ・倍率の組み合わせ。
- マルチモニターの実機操作。座標変換は合成画像のテストで確認した。
- 画像によるクリックの実機再生。照合は合成画像で確認した。
- 任意の他アプリと競合するホットキーの検出・抑止。

Mac実機とChromeの実際の画面で追加検証するまで、両OS・全用途を検証済みとは扱わない。
